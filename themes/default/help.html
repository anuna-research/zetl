ztl — help

Bi-directional wikilink graph CLI with optional defeasible reasoning, vault history, and a multi-user collaborative web UI. To override this page, drop a help.html in .ztl/themes/<theme>/.

Install

Requires a Rust toolchain (rustup). Clone the repo, then install the variant you want:

git clone https://codeberg.org/anuna/ztl
cd ztl

# wikilink features only
make install

# with defeasible reasoning
cargo install --path . --features reason

# with vault history (jj-backed temporal snapshots)
cargo install --path . --features history

# everything (reasoning + history + semantic search + MCP)
cargo install --path . --features "reason,history,semantic,mcp"

Collaboration mode (--collab) is always available. SPL-based access control needs --features reason.

Quick start

# point ztl at any vault of markdown files
ztl -d ./my-vault index            # build/refresh the link index

# explore the graph
ztl -d ./my-vault links "Some Page"
ztl -d ./my-vault backlinks "Some Page" --depth 2
ztl -d ./my-vault path "Page A" "Page B"

# search and validate
ztl -d ./my-vault search "query"
ztl -d ./my-vault check

# this web UI
ztl -d ./my-vault serve            # http://localhost:3000

# static export
ztl -d ./my-vault build            # writes ./dist

Tip: when run from inside the vault directory, you can omit -d.

Common commands

  • ztl index — build/refresh the link index
  • ztl links <page> / ztl backlinks <page> — graph queries
  • ztl path A B — shortest link path between two pages
  • ztl similar <name> — fuzzy page-name match
  • ztl search "query" — full-text search (--regex for patterns)
  • ztl check — dead links, orphans, syntax/SPL diagnostics
  • ztl blocks <page> — content-addressable block hashes
  • ztl view <page> — Xanadu two-pane page viewer
  • ztl serve / ztl build — web UI / static site
  • ztl --help — full CLI reference

History & time travel

Built with --features history:

ztl history log                       # graph evolution timeline
ztl history page "Some Page"          # page evolution
ztl --at "3 days ago" links "Page"    # query any read-only command at a point in time
ztl watch                             # auto-snapshot on file changes

Reasoning

Built with --features reason. Embed Spindle Lisp in ```spl code blocks or standalone .spl files, then:

ztl reason status                     # vault-wide conclusions
ztl reason explain "release-candidate" --format natural
ztl reason why-not "docs-updated"
ztl reason conflicts --suggest

Collaboration

# first-time setup (saves a 12-word recovery phrase)
ztl serve --collab --init-owner --owner-name Alice

# subsequent runs
ztl serve --collab

# invite a collaborator (link copies to clipboard)
ztl invite --as Alice --role editor

Roles: reader, editor, admin. Authentication uses WebAuthn passkeys with BIP39 mnemonic recovery. Real-time co-editing syncs over WebSocket via a Peritext CRDT.

Customising

  • Themes: override Minijinja templates in .ztl/themes/<name>/ (base.html, index.html, page.html, folder.html, help.html, …). Missing templates fall back to the bundled defaults. Activate with --theme <name>.
  • Static assets: drop CSS/JS/images in .ztl/themes/<name>/static/ — served at /_static/.
  • Hooks: executable scripts in .ztl/hooks/ at pre-build, post-build, post-index, post-check, pre-serve, on-save, on-agent, on-access-request. Receive vault context as JSON on stdin.
