## Shared definitions

### `ast_version`

Exact two-component schema version emitted by zetl (e.g. "1.0", "1.2"). Hook manifests declare a semver *range* (REQ-3215); this field is always a point version.

Pattern: `^\d+\.\d+$`

Example: `"1.0"`

### `position`

Source-text position of a node. Lines and columns are 1-indexed and inclusive, matching CommonMark's source-map convention.

| Field | Type | Notes |
| --- | --- | --- |
| `start_line` | integer ≥ 1 | 1-indexed, inclusive |
| `start_col` | integer ≥ 1 | 1-indexed, inclusive |
| `end_line` | integer ≥ 1 | 1-indexed, inclusive |
| `end_col` | integer ≥ 1 | 1-indexed, inclusive |

Every node carries a `position` object; the field tables below omit it for brevity.

### `frontmatter`

Parsed YAML frontmatter rendered as a JSON object. Attached to the Document root; not a child node. Arbitrary user-defined keys are permitted.

Attached to the `Document` root as an arbitrary JSON object (parsed from YAML). Absent when the source has no frontmatter.

## Document

*Root-level.*

Root of a zetl-ext AST document. Carries the schema version, optional parsed frontmatter, and the sequence of top-level block children.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `ast_version` | [`ast_version`](#shared-definitions) | yes |  |
| `children` | array of [`block`](#shared-definitions) | yes |  |
| `frontmatter` | [`frontmatter`](#shared-definitions) | no |  |

**Canonical example**

```json
{
  "ast_version": "1.0",
  "type": "Document",
  "position": { "start_line": 1, "start_col": 1, "end_line": 3, "end_col": 1 },
  "frontmatter": { "title": "Hello" },
  "children": [
    {
      "type": "Paragraph",
      "position": { "start_line": 3, "start_col": 1, "end_line": 3, "end_col": 6 },
      "children": [
        { "type": "Text", "position": { "start_line": 3, "start_col": 1, "end_line": 3, "end_col": 6 }, "text": "Hello" }
      ]
    }
  ]
}
```

**HTML rendering expectation**

Renders as the body of the page — children are emitted in order. `frontmatter` is not rendered; it is exposed to templates via the `page.meta` surface.

## List

*Block-level.*

Ordered or unordered list. `start` is null for unordered lists; for ordered lists it is the first item's number (default 1).

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `children` | array of [`ListItem`](#listitem) | yes |  |
| `ordered` | boolean | yes |  |
| `start` | integer \| null | no | min 0; `null` for unordered lists |
| `tight` | boolean | yes |  |

**Canonical example**

```json
{
  "type": "List",
  "position": { "start_line": 1, "start_col": 1, "end_line": 2, "end_col": 5 },
  "ordered": false,
  "tight": true,
  "start": null,
  "children": [
    {
      "type": "ListItem",
      "position": { "start_line": 1, "start_col": 1, "end_line": 1, "end_col": 5 },
      "children": [
        {
          "type": "Paragraph",
          "position": { "start_line": 1, "start_col": 3, "end_line": 1, "end_col": 5 },
          "children": [
            { "type": "Text", "position": { "start_line": 1, "start_col": 3, "end_line": 1, "end_col": 5 }, "text": "one" }
          ]
        }
      ]
    }
  ]
}
```

**HTML rendering expectation**

Renders as `<ul>` when `ordered=false`, `<ol>` when `ordered=true`. When `ordered=true` and `start` differs from `1`, the renderer emits `start="{start}"`. `tight=true` suppresses paragraph wrappers around single-paragraph items.

## CodeBlock

*Block-level.*

Fenced or indented code block. `fenced` distinguishes the two; `lang` and `info` are null for indented blocks. The raw block content (without the fence delimiters) lives in `text`.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `fenced` | boolean | yes |  |
| `info` | string \| null | yes | `null` when absent |
| `lang` | string \| null | yes | `null` when absent |
| `text` | string | yes |  |

**Canonical example**

```json
{
  "type": "CodeBlock",
  "position": { "start_line": 1, "start_col": 1, "end_line": 3, "end_col": 4 },
```

**HTML rendering expectation**

Renders as `<pre><code class="language-{lang}">…</code></pre>` when `lang` is set, or `<pre><code>…</code></pre>` otherwise. `text` is HTML-escaped and emitted verbatim — the block preserves newlines.

*Block-level.*

A fenced code block whose info string is exactly `spl`; promoted to a first-class node so transform hooks can operate on SPL source without string-matching info strings. `text` holds the raw SPL source between the fences.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `info` | string \| null | no | `null` when absent |
| `text` | string | yes |  |

**Canonical example**

```json
{
  "type": "SplBlock",
  "position": { "start_line": 1, "start_col": 1, "end_line": 3, "end_col": 4 },
  "info": "spl",

```

**HTML rendering expectation**

By default renders as a fenced code block with `info="spl"` — i.e. `<pre><code class="language-spl">…</code></pre>`. Themes or transform hooks may replace this with structured output (e.g. an interactive task-list widget).

## Embed

*Block-level.*

Obsidian-style transclusion (`![[target]]`, `![[target#heading]]`, `![[target#^block-id]]`). Block-level. `heading` and `block_id` are mutually exclusive in practice but both are permitted by the schema; consumers may treat both-set as a diagnostic.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `block_id` | string \| null | yes | `null` when absent |
| `heading` | string \| null | yes | `null` when absent |
| `target` | string | yes |  |

**Canonical example**

```json
{
  "type": "Embed",
  "position": { "start_line": 1, "start_col": 1, "end_line": 1, "end_col": 16 },
  "target": "Alpha",
  "heading": null,
  "block_id": null
}
```

**HTML rendering expectation**

Renders as the resolved transclusion: the target page's fragment is inlined at the embed position. When `heading` is set, only that heading's subtree inlines; when `block_id` is set, only the referenced block inlines. Unresolvable embeds render as a broken-link placeholder `<span class="zetl-embed-missing">![[target]]</span>`.

## SoftBreak

*Inline-level.*

A soft line break (single newline within a paragraph). Renders as a space or newline depending on the renderer.

No fields beyond `type` + `position`. Discriminator: `"type": "SoftBreak"`.

**Canonical example**

```json
{
  "type": "SoftBreak",
  "position": { "start_line": 1, "start_col": 6, "end_line": 1, "end_col": 7 }

```

**HTML rendering expectation**

Renders as a literal newline character (`\n`) inside the output. Most browsers collapse this to whitespace; authors who want a visual break should use `LineBreak`.

## Wikilink

*Inline-level.*

Obsidian-style wikilink (`[[target]]`, `[[target|alias]]`, `[[target#heading]]`, `[[target#^block-id]]`, or any combination). Inline-level. `alias`, `heading` and `block_id` are null when absent from the source.

| Field | Type | Required | Notes |
| --- | --- | --- | --- |
| `alias` | string \| null | yes | `null` when absent |
| `block_id` | string \| null | yes | `null` when absent |
| `heading` | string \| null | yes | `null` when absent |
| `predicates` | array of object | no |  |
| `target` | string | yes |  |

**Canonical example**

```json
{
  "type": "Wikilink",
  "position": { "start_line": 1, "start_col": 1, "end_line": 1, "end_col": 19 },
  "target": "Alpha",
  "alias": "the alpha",
  "heading": "Intro",
  "block_id": null
}
```

**HTML rendering expectation**

Renders as `<a href="{resolved}" class="zetl-wikilink">{label}</a>`. `{resolved}` is the slug for `target` (with `#heading` or `#^block-id` appended when set). `{label}` is `alias` when set, otherwise `target`. Unresolvable wikilinks render as `<a href="#" class="zetl-wikilink zetl-wikilink-missing">{label}</a>`.
